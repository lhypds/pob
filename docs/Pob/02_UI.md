
UI
==

The Pob window is an overlay: it sits above the app you want driven, and what
it frames is what the screenshots show and what the clicks are aimed through.

<img width="560" alt="image" src="https://github.com/user-attachments/assets/64db922a-4104-43c7-aa33-6511bbe484c9" />

The toolbar shows this instance's ID (`pb-<uid>`) at the left, beside the window buttons; the action
buttons are packed against the right edge, in this order (left to right). On Windows and Linux the
name `Pob` sits in front of the ID, and clicking it shows the version — macOS keeps both in the
menu bar at the top-left of the screen instead, under `Pob ▸ About Pob`.

| # | Button | Description |
|---|--------|-------------|
| 1 | Settings | Open the settings file |
| 2 | Logs | Open the logs folder |
| 3 | .log | Open this instance's log — `<instance>/instance.log`, what a run actually did. Option/Alt-click opens `app.log` instead, the record across instances |
| 4 | Macro PSL | Open `src/main.macro.psl`, this instance's [macro](03_Macro%20PSL.md) entry point |
| 5 | Record | Start/stop recording into `src/main.macro.psl`; when it already has statements, asks whether to clear them or keep recording after them |
| 6 | Execute / Stop | Replay `src/main.macro.psl`, filling its `:: … ::` slots as it goes; stop if already running. A macro is read before it is played, and one with a line Pob cannot read puts up **Macro problems** instead of moving the cursor |
| 7 | Target | Hover to inspect pixel coordinates; click to copy `x, y` to clipboard |
| 8 | Crop | Drag to select a region; release to copy `x, y, width, height` to clipboard |
| 9 | Screenshot | Capture the content area to `<instance>/screenshots/`; while recording, also appends `takeScreenshot()` to the macro |
| 10 | Click-Through | Toggle whether clicks pass through the window to apps behind it (on by default) |
| 11 | Lock | Lock the window to its size, and to what it frames: it can still be dragged, and every window under it is dragged with it. The instance keeps it: a window left locked comes back locked on the next run |
| 12 | Reset | Send the mouse back to its home corner |

* Target and Crop are helper functions for when you hard to describe the GUI element.  
* The lock is what holds a macro's coordinates. Every position a macro records is relative
  to the frame, so the frame has to stay put — but only its *size* really has to: a move
  costs nothing if what the frame is over moves with it, which is what the lock does. Play
  and Record turn it on themselves; turning it back off is your call.  
* A window is carried when it overlaps the content area at all — the same test that decides
  whether it turns up in a screenshot, so what moves is what you can see. Which windows
  travel is settled when the frame is picked up, and holds for that whole drag.  
* Carrying follows drags only: a window placed by the system, a resize, and a maximized or
  full-screen window below are all left alone. On macOS it needs the same Accessibility
  permission the mouse and keyboard already use.  
* The virtual mouse — the pointer the macros, the AI and the remote clients aim with — is
  drawn in the window from the moment Pob starts, parked at its home corner (20, 20).  

Clicking the instance badge copies this machine's dashboard —
`http://192.168.1.40:8033` — which is what a phone's browser is pointed at:
the index page, and links on to the control and view pages from there. With the
[server](09_Server.md) turned off there is no address, and the bare ID is copied
instead.


Fullscreen
----------

```
pob launch --fullscreen
```

Started this way, the window is the screen and none of the above is on it: no
titlebar, no toolbar, no window buttons, no badge. The overlay covers the whole
display — over the menu bar, the Dock and the taskbar as well — and what it
frames is everything.

Nothing on screen is Pob's to click, so the twelve buttons are the terminal's
instead: `pob start` and `pob stop` for Execute, `pob record start` and `pob
record stop` for Record, `pob screenshot`, `pob lock`, `pob clickthrough`, and
`pob kill` to quit it — see [CLI](07_CLI.md). Clicks go on passing through to
the applications below, so the machine is still yours while Pob sits over it,
and `pob relaunch` brings the window back.

The mode belongs to the run and not to the instance: nothing is written down, so
the next ordinary launch is the window described above, at the size and place it
was last left at.
